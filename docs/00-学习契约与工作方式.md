# 00 · 学习契约与工作方式

> 这份文档规定"我们俩怎么配合"。看一遍，认可就按这个来；不认可，我们改。

---

## 一、核心分工

| 角色 | 谁做 | 做什么 |
|---|---|---|
| 路线 / 讲解 / 验收 / 纠错 | 我（老师） | 给任务卡、讲原理、出验收标准、review 你的代码、指出坑 |
| **敲代码** | **你** | 100% 的代码由你亲手敲，包括你觉得"很简单"的那些 |

**这条不许破。** 你的目标是"亲手把它逐渐做成"，不是"让 AI 生成一个项目"。代码一旦是复制来的，遇到 bug 你没有任何调试直觉，Phase 3 之后必然崩。

---

## 二、三级提示规则（你问我问题的默认规则）

卡住的时候，**不要直接问"怎么做"**。用这个模板：

```text
【任务】我在做 M2-3 的 header 透传
【现象】curl 网关时 backend 收到的 Host 变成了 localhost:8081
【我试过】我打了日志，发现是 HttpRequest.newBuilder() 里我显式设了 .header("Host", ...)
【报错/日志】
<原文粘贴，不要转述>
【我想要】告诉我该往哪个方向查，别直接给代码
```

我会按三级给你：

| 级别 | 我给什么 | 什么时候用 |
|---|---|---|
| **L1** | 反问 + 概念引导，不给方向性答案 | 默认。我说"你先自己想" |
| **L2** | 定位到文件 + 方法签名 + 伪代码 | 你试了 30 分钟没进展 |
| **L3** | 参考实现（可运行片段） | 你说"给我 L3"，或你连续 2 次卡在同一个点 |

**默认永远从 L1 开始。** 我要的不是你敲得快，是你每敲一行都知道为什么。

## 三、单个任务的循环（每个小任务都走这 5 步）

```text
① 读任务卡（3 分钟）     —— docs/任务看板.md 里那一条
② 我讲原理（5~15 分钟）  —— 你确认"懂了"再动手
③ 你敲代码（主要时间）   —— 禁止跳过运行
④ 验收（对着清单逐条打勾）—— 必须有可运行的证据（curl 输出 / 日志 / 截图）
⑤ 复盘 + 提交            —— notes/ 写 3 行，git commit
```

**没通过第 ④ 步，不许进下一个任务。** 这是这个项目不会烂尾的唯一保证。

---

## 四、每天的 3 小时怎么切（时间盒）

```text
00:00 ~ 00:45   学原理（我讲 + 你查 + 你追问）
00:45 ~ 02:15   敲代码（中途卡住超过 20 分钟就按三级规则提问）
02:15 ~ 02:40   验收 + 压一下边界（故意搞坏它，看它怎么坏）
02:40 ~ 03:00   写 notes/ + git commit + 更新看板
```

**每 45 分钟离开椅子 5 分钟。** 3 小时连续盯屏幕，第 3 小时基本是废的。

## 五、笔记制度：notes/ 目录

触发式学习的关键产物。**每个知识领域一个文件**，不是读书笔记，是"我撞到过的问题"。

```text
notes/
├─ 01-http与网络.md
├─ 02-java与spring.md
├─ 03-redis与分布式.md
├─ 04-可观测性.md
└─ 05-llm推理系统.md
```

每条统一用这个四段式，10 行以内：

```markdown
## [M2] 为什么 hop-by-hop 头不能透传
- 现象：透传 Connection: keep-alive 后，客户端连接复用行为变得很怪
- 原因：这类头描述的是"这一跳"的连接，由每跳自己决定，转发会污染链路语义
- 结论：透传前先过一遍黑名单：Connection/Keep-Alive/TE/Trailer/Transfer-Encoding/Upgrade/Proxy-*
- 还欠：TE 和 Trailer 在 chunked 里具体怎么用？待 Phase 2 流式时回看
```

**"还欠"这一栏最重要** —— 它就是你知识树的分叉点。

## 六、Git 规范（现在就用，Phase 4 写简历时要靠它）

```text
main               永远可运行（能 mvn spring-boot:run 起来）
task/M2-header-透传  单个任务一个分支（可选，你熟练后再用）
```

提交信息：

```text
feat(M2): 透传 end-to-end header，过滤 hop-by-hop
fix(M2): 修复 query string 中文未编码导致 400
docs(M2): 补 notes 里 hop-by-hop 的结论
```

一个任务一个 commit。**不要攒一周再提交** —— 你后面会想回看"我当时的实现长什么样"，那是很好的教学素材。

---

## 七、几条硬性禁止

1. ❌ 不复制粘贴网上的完整实现（贴 3 行查语法可以，贴整个类不行）
2. ❌ 不写超过 150 行还没运行过的代码
3. ❌ 不跳过验收清单
4. ❌ 不在代码里硬编码任何 API Key（用环境变量，`.gitignore` 挡掉 `*.local.yml`）
5. ❌ 不同时学两个新东西（比如"一边学 WebFlux 一边学 Redis"，必崩）
6. ❌ 不因为"这个功能太简单"就让我替你写

---

## 八、你要随时能回答的三个问题（费曼检验）

每个里程碑结束时，我会随机抽问你：

1. **这个功能，数据从哪来，到哪去？**（画得出时序图）
2. **如果它坏了，你会先看哪三个地方？**（调试直觉）
3. **不用它，手写要多少行？它帮你省了什么？**（技术选型的判断力）

答不出来，说明这个里程碑是"抄完的"不是"做过的"——回去重做验收。
