# 01 · 路线图与里程碑

> 对应《简介.md》的四个阶段，但拆成了可以打勾的 13 个里程碑。

---

## 一、最终目标（一句话）

> 从一个只会转发 HTTP 请求的 Mini Gateway，亲手把它长成一个支持 **多模型路由、流式转发、限流、负载均衡、可观测性、vLLM 本地推理、Agent、MCP** 的小型 AI Gateway。

**真正的产出不是代码，是你脑子里那张"一个 AI 请求从 Client 到模型中间到底发生了什么"的地图。**

## 四、技术选型（以及"为什么是它"）

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | **Java 17** | Spring Boot 3 的最低要求；record / 文本块 / switch 表达式都够用 |
| 框架 | **Spring Boot 3.5.x**（IDEA 生成的最新 3.x） | 你已有基础，生态最全 |
| 构建 | **Maven 3.9.10**（已装，阿里云镜像已配） | 不用再学 Gradle |
| Phase 1 的 HTTP 客户端 | **JDK 自带 `java.net.http.HttpClient`** | 先手写，你才会真正懂 header/超时/流式。**不要一上手就用框架** |
| Phase 2+ 的 HTTP 客户端 | 换成 **Spring `RestClient` / `WebClient`** | 体验"框架替我做了什么"，再对比回 JDK 版本 |
| 配置 | `application.yml` → 后期加配置中心 | 先别上 Nacos，够用就行 |
| 缓存/计数 | **Redis**（WSL2 里装） | 限流、统计、缓存 |
| 指标 | **Micrometer + Prometheus + Grafana** | 事实标准 |
| 本地推理 | **vLLM**（WSL2 + CUDA，RTX 4060 8G 跑 1.5B） | 唯一能直观看到 continuous batching 的方式 |
| 协议 | **OpenAI 兼容 API** | 客户端零改造，MCP/Agent 生态全都吃这套 |

```text
new_project/                     ← 仓库根（要 git init）
├─ 简介.md                        ← 你的原始想法
├─ docs/                          ← 计划、任务卡（我写）

│  ├─ 01-路线图与里程碑.md
│  ├─ 02-环境搭建.md
│  ├─ 03-Phase1-网关骨架.md
│  ├─ 04-Phase2-LLM网关.md
│  ├─ 05-Phase3-AI-Infra.md
│  ├─ 06-Phase4-推理与Agent-MCP.md
│  └─ 任务看板.md
├─ notes/                         ← 知识笔记（你写，触发式）
├─ mock-backend/                  ← 你手敲的"假后端"（M1 用）
└─ gateway/                       ← 你手敲的网关本体
```

**为什么 `mock-backend` 单独一个项目？**
因为 M1 你要亲手做一次"后端"，才知道 header 和 body 在两端分别是什么样。自己写的两端对不上时，你会立刻知道是谁的问题。这比用 httpbin 学得快 10 倍。

两个独立 Maven 项目，先不要搞父子 pom —— Phase 3 需要多模块时再重构，那次重构本身就是一堂课。

## 六、每个阶段的"出门检验"

每个里程碑结束，你要能**不看笔记**回答这些：

**Phase 1 结束**
- HTTP 请求报文有哪几行？`Content-Length` 和 `Transfer-Encoding: chunked` 什么时候用哪个？
- 超时至少有哪三种？分别对应什么故障？
- 网关转发时，为什么有些 header 绝不能原样透传？

**Phase 2 结束**
- OpenAI 的 `chat/completions` 请求体里，`stream: true` 之后响应体长什么样？
- 为什么流式不能用"一次性读完再返回"？背压是什么？
- 上游返回 429 / 500 / 超时，网关分别该怎么处理？为什么 500 不能盲目重试？

**Phase 3 结束**
- 为什么限流要放 Redis？单机版令牌桶和分布式版差在哪一行？
- 什么请求可以缓存？`temperature > 0` 的请求为什么不可以？
- p95 和平均延迟差很多，说明什么？

**Phase 4 结束**
- 为什么 vLLM 并发 16 时总吞吐比并发 1 高很多，但单请求延迟不一定更低？
- KV Cache 占显存，和 `max-model-len` 什么关系？
- Agent 和"直接调模型"的本质区别是什么？
- MCP 解决的是"谁能用工具"还是"工具怎么被描述和发现"？

答不上任何一条 → 回看 `notes/` 对应章节，或直接来问我。**这些问题的答案就是你面试时的答案。**
